## State restoration

T3 desktop restores less than the spec implies. Route and scroll position are not restored across a relaunch in T3, and CandyWrapper already goes further on the route.

What T3 restores across a relaunch:

- Window frame and maximized flag. `apps/desktop/src/settings/DesktopAppSettings.ts:31,65-71` stores `mainWindowBounds` and `mainWindowMaximized`. `apps/desktop/src/window/DesktopWindow.ts:383-400` reads them and checks them against the connected displays (`resolveInitialMainWindowBounds`). `:455-480` saves on move and resize. `:840` re-maximizes.
- Open thread or route. Not restored. The window loads the app root, and `routes/_chat.index.tsx:36-48` opens a new draft for the most recently active project.
- Sidebar width. `components/threadSidebarWidth.ts:1` (`chat_thread_sidebar_width`), read at `components/AppSidebarLayout.tsx:329` through `hooks/useResizableWidth.ts:64`.
- Sidebar collapsed. Not restored. `components/ui/sidebar.tsx:25,126` writes a `sidebar_state` cookie that nothing reads, so T3 always starts open (also in `docs/research/recovered/ui-components-b.md:1235`).
- Sidebar shelf expansion (Settled, Snoozed, Working). `components/Sidebar.tsx:299-301` localStorage keys.
- Right panel tabs per thread. `rightPanelStore.ts:90` (`t3code:right-panel-state:v2`), plus the closed-tab stack in `closedViewStore.ts`.
- Diff panel scope per thread (branch or unstaged, base ref). `diffPanelStore.ts:121` (`t3code:diff-panel-state:v1`).
- Terminal drawer state. `terminalUiStateStore.ts:30`.
- Preview panel width. `components/preview/PreviewPanelShell.tsx:19-28`.
- Drafts with text, image attachments and context. `composerDraftStore.ts:89` (`t3code:composer-drafts:v1`), attachments at `:392` (`persistedAttachments`).
- Thread last-visited and changed-files expansion. `uiStateStore.ts:6,40-45`.
- Scroll position. In memory only. `components/chat/timelineScrollAnchoring.ts:162-175` keeps 100 entries and loses them on relaunch.

What CandyWrapper restores today:

- Window frame. `App/Sources/AppDelegate.swift:227` (`setFrameAutosaveName("MainWindow")`), with `NSQuitAlwaysKeepsWindows` in `App/Resources/Info.plist:42`. AppKit restores the frame. Nothing checks it against the displays, and the zoomed flag is not stored separately.
- Last open thread, scoped by environment. `App/Sources/ThreadSession.swift:570,593,955-966`. It waits for the thread's environment to connect before it falls back to a new draft.
- Sidebar width. `Packages/CandyKit/Sources/DesignSystem/Components/SidebarView.swift:14,60-69,98,151`.
- Right panel tabs per thread and the closed stack. `App/Sources/FilesController.swift:61-62,119-142` (200 threads).
- Terminal drawer. `App/Sources/TerminalController.swift:684-694`.
- Preview panel width. `Packages/CandyKit/Sources/Features/Thread/ThreadPanelView.swift:546,1017`.
- Draft text and draft sessions. `App/Sources/ComposerController.swift:148,159-165`, plus pending SnapShot captures (`:2436`) and review-comment records (`:917`).
- Opened-thread cache on disk. `App/Sources/Environments.swift:37` (`ThreadCache`), so the first frame needs no download.

## T3 Connect cloud state

The switch is disabled in `App/Sources/SettingsHostAccess.swift:202-209`. The port is the body of T3's `reconcileCloudState` (`cloud/useCloudLinkController.ts:85-190`) plus the link and unlink calls in `cloud/linkEnvironment.ts`.

What exists: `EnvironmentHTTP.cloudLinkState` and `setCloudPreferences` (`Packages/CandyKit/Sources/T3Client/EnvironmentHTTP.swift:107-114`, so publish and hold-webhooks already work), the relay install flow (`App/Sources/DesktopManagedController.swift:104-129`), the Clerk `t3-relay` token (`T3Client/Connect/ClerkClient.swift:76,219`), `RelayClient.deregister`, and `FakeT3Connect.swift` for offline tests.

What the port needs:

1. Two relay calls missing from `T3Client/Connect/RelayClient.swift` (it has list, deregister, status, connect only): `POST /v1/client/environment-link-challenges` with `{notificationsEnabled, liveActivitiesEnabled, managedTunnelsEnabled}`, and `POST /v1/client/environment-links` with `{proof, ...same flags}`. Contracts at `packages/contracts/src/relay.ts:1070-1100`. Both take the Clerk JWT as bearer.
2. Three environment HTTP calls missing from `EnvironmentHTTP.swift`: `POST /api/connect/link-proof`, `/api/connect/relay-config`, `/api/connect/unlink` (`packages/contracts/src/environmentHttp.ts:678-709`).
3. The link sequence from `linkEnvironment.ts:262-350`: install the relay client when the mode is managed, get a challenge, get the server's proof (endpoint `127.0.0.1:<port>` plus `providerKind` `cloudflare_tunnel` or `manual`), post the link, check the returned environment id and provider kind match, then post `relay-config`. Unlink calls `/api/connect/unlink` first, then `DELETE /v1/client/environment-links/:id` with a token if one exists (`:215-250`). An unlink must still work when the token read fails.
4. The decision logic from `useCloudLinkController.ts:107-188`: want = managed tunnel or publish. Neither wanted means unlink. Otherwise link again only when the managed mode changed or the environment is not linked, then set the publish preference. Re-read link state after every exit. Scopes `relay:read` and `relay:write` are checked first.
5. Swap `isEnabled: false` in `SettingsHostAccess.swift:209` for the call, and fold the publish and hold-webhooks rows through the same function so one request can carry both.
6. A relay URL setting. T3 reads `VITE_T3CODE_RELAY_URL` (`cloud/publicConfig.ts:46`). CandyWrapper has `RelayClient.productionURL`; confirm it is the same host.

Size: medium for code and unit tests against `FakeT3Connect`, plus a half day on a real account. Blockers: it needs the user's own T3 Connect account and a deliberate test, because a link writes relay credentials into whichever server it targets. It must run against the sandbox server only, never `~/.t3`. CLAUDE.md forbids restarting the live service, and the first link may restart the tunnel.
