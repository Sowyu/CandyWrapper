## Reproduction fidelity

- `files-actions-harness.py` extracts the three real methods and preserves their awaits and mutable second target lookup. Its composer fake clears text exactly as production does. It can validate F1/F2 callback ownership; it does not validate JSON encoding, host permissions or AppKit navigation. Direct target reassignment represents a production-reachable transition, not a bypass of a navigation lock. Its exit 0 means the bugs reproduced, **not that the application passed a correctness test**.
- `scripts/audit-composer-recovery` extracts real failure/retry methods. Its current-key persistence fake omits questions and queued edits, appropriately matching its ordinary-thread scenario. Its fake Send duplicates `:1853-1854`, but omits send gates and networking: C3 requires the real ready-upload/current-target gates to permit the send. Static review supports those conditions. Its intentional failing exit must not be described as a failing app build.
- `scripts/audit-session-actions` retains the production save method and real temporary file operations. Its fake download returns a file and HTTP response for 403/404, preserving ordinary URLSession behavior; the production server's explicit 404 supports that fault. The fake save panel grants replacement immediately. It validates replacement/error handling after acceptance, not picker/toast routing. The fake download does not suspend after marking finished, so its main-actor waiter cannot read halfway through the synchronous remove/move sequence.
- Image tests use the real surface. Releasing nil after cancellation matches the real error-to-nil closure; keeping the cancelled task suspended until release does not manufacture a missing guard. The malformed-data test establishes only invalid-image feedback. Neither tests IMG-2.
- Thread tests use real reducers/views. Lowering the worker threshold forces the production asynchronous path and can establish the intermediate invariant. It does not show that a human can click in that interval at production size. The paging test forwards exactly the history field used by the session. The Markdown stress test is a parser/layout screening benchmark, not input-to-paint or thread-open latency.
- Transport's Pong test uses the real feed/connection with fake socket/time and preserves the pending-first-snapshot dependency. Its `connection.isClosed` assertion selects one possible recovery design; a future correct owner-level timeout could keep the socket open. The failure should be interpreted as the current missing recovery mechanism, not a requirement that every fix close the socket. No supplied test covers Transport T1's app-level endpoint rotation.
- The hidden-terminal harness extracts the real bounded buffer and marker scanner; its ASCII snapshot shape matches the declared `MCPServerEntry` fields (`AgentConfig.swift:17-25`). It proves truncation versus complete-line scanning, not PTY delivery or exact real-world config counts. OH-5 uses the real store but substitutes controller callbacks; the actual controller has no busy reset when the queued run starts (`ConnectorsController.swift:43-51`), which preserves the claimed limited effect.

None of the intentional failures is a new ordinary-suite failure. Do not combine their differing exit conventions into one pass/fail count. No compiler or execution results are claimed here.
