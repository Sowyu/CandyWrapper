# Milestone 10 report, 2026-10-12

Milestone 10 has two halves (PROGRESS.md, "Milestone 10"): a stress test for glitches and performance, and a side-by-side check against T3 Code Nightly. The stress half is done. The side-by-side half covered the flows the user lives in; the full parity checklist sweep and the newer Nightly's UI are still open. Detailed reports: `m10-side-by-side-2026-10-12.md`, `m10-abuse-2026-10-12.md`, `m10-load-2026-10-12.md`.

## Part 1: stress

### Data pipeline fuzzing

Seeded, randomized sequences built from the recorded transcripts hit the shell reducer, ThreadStore, ThreadReducer, WorkLog and the timeline pipeline: out-of-order and duplicated deltas, reconnect snapshots mid-turn, retries, interrupts, subagents, history pages during live deltas, and cache restore. Invariants are checked after every step. The default run is part of `swift test`; `CW_STRESS_ITERATIONS` sets a long run.

- The long run passed 1,500 seeds per configuration. Step time p50 0.14 to 0.25 ms, p99 1.06 to 2.11 ms, worst 47.9 ms (Debug).
- A sent message showed twice when a bounded snapshot or older page carried its row without the message. It now follows T3's `serverAcknowledgedUserMessageIds`.
- A Load earlier request cancelled by a view move left the control loading. It now follows T3's `clearActiveHistoryLoading`.

### Abuse and failure

The app ran against its own server behind a fault-injecting TCP proxy while turns streamed. No crash in any scenario.

- The app recovered by itself, with its stored thread matching the server, from a dropped connection, a 30 s stall, the server killed and restarted, a revoked session, the app killed mid-turn, and corrupt, truncated and duplicated frames.
- Fast thread switching, resizing, hard scrolling, shortcut, queue and steer spam, and answering a question while switching lost or duplicated nothing. Memory settled at 71 to 75 MB.
- A frame cut off mid-message hung the connection for good. The client now pings after 5 s of silence while a reply is owed, as T3's Effect client does.
- Every dialog built a Core Image context for its backdrop blur, a 120 to 255 ms freeze on each Cmd+K. A small vImage blur replaced it.
- Cmd+1 to 9 and Shift+Cmd+[ ] left a stale sidebar multi-selection. They now clear it, as in T3.
- Still open: a fresh Debug app holds the main thread 170 to 200 ms on its first thread open, not yet measured in Release. One 1.3 s hang did not reproduce. A connection cut while nothing is owed waits for the next request, activation or wake.

### Load and endurance

1,580 threads across five environments, threads of 2,000 to 5,000 messages, a 4.1 MB tool output, a 17,500-line diff, an 18,000-line code block, and 18 turns in parallel.

| Measure | Before | After |
|---|---|---|
| Live sidebar at launch, 5 environments | 2.0 to 2.4 s | 0.43 to 0.79 s |
| Cmd+K, per keystroke | 150 to 270 ms | 28 to 56 ms |
| Main-thread time in a 6 s sidebar scroll | 511 ms | 78 ms |
| Minimap marks in a 6 s scroll of 5,000 messages | 245 ms | 54 ms |
| First frame of the 18,000-line code block | 1.75 s, 384 MB | 0.92 s, 294 MB |
| Sidebar sort and Lineage work per shell change | 3.5 and 1.8 ms | 0.71 and 0.36 ms |

Endurance: 135 minutes on a Release build, a turn every ten minutes and a thread switch every two. All 14 turns completed, no crash, no growth: memory 73 to 79 MB, CPU 0.14 to 0.31%.

Still open: opening the 18,000-line code block still takes 0.9 s and 294 MB (all lines are laid out up front); the sidebar rebuilds fully on every change and every relative-time tick (about 20 ms at 1,580 threads).
