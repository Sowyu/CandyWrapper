## 1. Wire changes

### Breaks

1. `github` and `bitbucket` server settings are gone, replaced by `sourceControlHosts` (4f63275ac, packages/contracts/src/settings.ts:824 and :1304; patch key at settings.ts ~1604). The server now serves no `github` or `bitbucket` key and drops them from patches, and it migrates old values on read (apps/server/src/serverSettings.ts `migrateLegacySourceControlSettings`). CW reads `settings.raw["github"]["tokens"]` (Features/Settings/SourceControlSettingsView.swift:726), `["github"]["hosts"]` (SourceControlCredentialsViews.swift:340) and `["bitbucket"]` (:187), and patches `github` (SourceControlSettingsView.swift:755) and `bitbucket` (SourceControlCredentialsViews.swift:230). Against a 2994 server the GitHub token, GitHub accounts and Bitbucket credential editors show empty, and saves are silently ignored. Everything else in Settings > Source Control still works. New shape: `sourceControlHosts.<kind>` is an open record, secrets are a redaction marker, per-host maps are sent whole. Which fields each host takes lives in its client definition (packages/source-control-github/src/client/definition.ts, ...-bitbucket, ...-gitcafe).

### Degrades

2. Model favorites, hidden models and model order are now server settings shared across clients (f84589527, settings.ts:1086 `favorites`, `providerModelPreferences`, patch keys `setModelFavorites` :1472, `setModelsHidden`, `setProviderModelOrder`, `migrateModelPreferences`). Official clients write them to the environment. CW keeps favorites in UserDefaults `CandyWrapper.modelFavorites.v1` (T3Store/ComposerSelection.swift:133) and prefs in client setting `providerModelPreferences` (T3Protocol/Domain/Settings.swift:112, Features/Settings/ProvidersSettingsView.swift:767). CW still runs, but its stars and hidden models no longer match what the official app shows for the same server.
3. Notification source gained `{kind:"system"}` for restart continuations (a7223f396, orchestrationV2.ts:1186). CW's `NotificationSource.kind` falls back to `background_task` for unknown kinds (T3Protocol/Domain/TurnItem.swift:238-246), so a restart continuation shows as a background task row, not the "T3 Code" notice. Same as old official clients.
4. `UsageProviderKind` gained `"pi"` (9afde1c6d, packages/contracts/src/usage.ts:41). CW's enum has no `pi` (T3Protocol/Domain/Usage.swift:16) and skips rows it cannot decode (:99, :158), so Pi usage is missing from charts. Nothing crashes.
5. `workspaceId` added to `ServerProviderAuth` (server.ts:77) and `UsageLimitSourceAccount` (providerUsageLimits.ts:96) (0be20c86c). Official clients now keep one email in two workspaces as two accounts. CW has no `workspaceId` handling, so it merges them.
6. Workflow coordinator subagents carry `workflow: {phases, agents, ...}` (b9afba59f, orchestrationV2.ts:736). CW ignores it and shows a plain subagent card with no phase or member list.
7. `promptCacheTtlMs` added to provider turn token usage (c727d1219, orchestrationV2.ts:1066). See part 3.
8. `lastSnoozeWakeAt` on app threads (0a4d78912, orchestrationV2.ts:408). CW derives snooze state from `snoozedAt` only (T3Store/SidebarModel.swift:327-356). A manual wake may reorder or reset inactivity differently from the official sidebar. Low impact.
