# Decisions

What the user decided and why, newest first. Check here before changing anything these cover.


- 2026-10-14: Glass Native keeps the real `NSToolbar` and `NSSplitViewController`, about 6 MB and 50 ms over classic Glass, instead of a frame-laid lookalike. The user answered "yes" to keeping them.
- 2026-10-14: agents may use the shared GUI screen while the user works on it, taking turns through `scripts/ui/screen-lock`.
- 2026-10-13: the user dropped the side-by-side check of every parity checklist row ("side by side isnt that important if its about ui parity"). Rows already checked stay ✅, the rest stay 🟡, and the findings so far are in `docs/research/sbs-keyboard-2026-10-13.md`. Fix a difference when someone reports it, not by sweeping the checklist.
- 2026-10-11, at the M7 demo: the user skipped T3's opt-in legacy sidebar (row 67, now n/a).

- 2026-10-10: One known difference from T3, to check in the milestone 10 side-by-side: editing a project action without touching its shortcut keeps the shortcut, where T3 drops it (WP7.7b). Everything else aims at T3's behavior as is.
- 2026-10-10: No GitHub token for the sandbox (the user: "just do whats best"). Pull request features are tested on fixtures taken from T3's own tests, and in milestone 10 read-only on the user's live T3 if it shows pull requests.
- 2026-10-10, the user's standing rule: after every big step (each merged work package) and every milestone, run a full review before moving on and show it to the user: `scripts/perf-review` (launch, idle CPU and wakeups, memory with the sidebar and with a huge thread, streaming CPU, micro-benchmarks, bundle size) compared with the previous saved run with regressions flagged, the whole test suite, fidelity numbers against the last run, and at milestones a code review of the milestone's diff (bugs, slow paths, leaks, security). No degradations ship silently.
- 2026-10-10: the work lives on GitHub at https://github.com/Sowyu/CandyWrapper (public). Work on `main`, commit as each piece lands, and push (`git push origin main`) after each commit batch; the user asked for both. Before the first push the whole history was scanned for secrets, the public IP and e-mail. GitHub auth is `gh` (official release in `../CandyWrapper-research/tools/gh/gh`, logged in as Sowyu through the device flow, token in the login Keychain, wired with `gh auth setup-git`). `m3-skeleton` is the old working branch name, kept on GitHub for history.
- 2026-10-10: T3 Connect sign-in route, final. The user left it to us ("whatever is best"). The CLI's OAuth token lists environments but can't connect (`dpop-token` only takes the `t3-relay` template JWT, `infra/relay/src/http/Api.ts:1020-1025,1638-1656`). CandyWrapper signs in natively through Clerk's Frontend API like T3's mobile app (docs/research/M-clerk-native.md): email code first, then password, native views, the Clerk client token in the Keychain, a fresh `t3-relay` JWT minted per relay call (60 s lifetime). No webview and no URL scheme. Left out: social OAuth (it would borrow T3's Android redirect `clerk://com.t3tools.t3code.callback` inside ASWebAuthenticationSession; ask the user before adding it) and passkeys (T3's associated domains list only T3's bundle ids). Risk: T3 can change its Clerk config; the durable fix is asking T3 to allowlist CandyWrapper.
- 2026-10-09: The app never starts a second server on a home that has one. `LocalServerDiscovery.discover` waits up to 20 s, then shows an error, when the runtime file names a live process that doesn't answer, or when T3's launch agent (`~/Library/LaunchAgents/com.t3tools.t3code.service.plist`, `T3CODE_HOME`) owns the home. On this Mac the service owns `~/.t3`, so the app only ever joins the live server there.

- 2026-10-09: Allow Remote Access (app menu). On keeps the app's own server running while CandyWrapper is idle, so the user's phone can reach this Mac. Off lets it stop after 10 idle minutes. Until the user picks, it follows whether T3 Connect is linked (`GET /api/connect/link-state`). Proposed to the user after they asked about reaching the Mac from Android; not explicitly confirmed.
- 2026-10-09: The app records the server it started (pid plus start time, and its own) in `~/Library/Application Support/CandyWrapper/owned-server.json`. On the next start, if that app process is gone, it stops exactly that server. Otherwise a crash would leave a server that later launches treat as someone else's and never stop.

- 2026-10-09: Server lifecycle on the user's laptop: CandyWrapper starts T3's server only when needed and stops it when idle or on quit, never during a running turn or a pending approval. It reuses an already-running T3 server instead of starting a second one, and launches its own server with the lowest-memory Node settings that measure fine. Claude agents keep running locally through it, and threads stay compatible with official T3. The launch shows cached sidebar state while the server starts.

- 2026-10-09: Webviews are allowed for the features that render web content in the official app (built-in browser and preview, HTML replies, MCP apps, Mermaid, HTML file preview, Clerk sign-in). Condition from the user: no background cost. Create the WKWebView only while its pane is visible, tear it down when hidden, never keep one alive or polling, and never load one at launch.
- 2026-10-09: T3 Connect may sign in as T3's own web client (`client_id` `t3-web`, Clerk template `t3-relay`), the same way the official web app does. The user approved borrowing that identity.
- 2026-10-09: Committing is approved, PNGs included, as long as no secrets leak. Checked before the first commit: text scan for tokens, keys and the user's e-mail, plus Vision OCR of all 98 screenshots. T3's Clerk publishable key appears in the docs; it is public in T3's own `.env.example`.

- 2026-10-09: Reference screenshots of the web client come from headless Chromium. Capture only, nothing ships. The MCP preview tool downscales to 1280 px wide, so captures use T3's downloaded chrome-headless-shell directly over the DevTools protocol. Reference size is 1100x780 CSS px at 2x, the official desktop app's default window (minimum 840x620, `apps/desktop/src/settings/DesktopAppSettings.ts:61`).
- 2026-10-09: The user chose to resume all 14 halted sub-agents only to write their reports.
- 2026-10-09: The user will install Xcode. Until then keep everything buildable with SwiftPM.
- 2026-10-09: Client benchmarks run on this Mac mini once a GUI session exists. No battery test is possible here, and the virtual display is 60 Hz at 1x.
- 2026-10-09: Research agents use `sonnet-medium`, never nested. The first research round used Opus max with nested agents and cost the user about $400.
