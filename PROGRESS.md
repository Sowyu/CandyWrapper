Gotchas found so far:
- Offscreen AppKit views only get a layer tree inside a window that has displayed once. `Snapshot` hosts the view in a hidden borderless window and calls `display()` first.
- A non-final `@MainActor` closure property in an `open` class trips a Swift 6.4 bug (getter symbol never emitted, link fails). Make such properties `final`.
- `NSGraphicsContext(bitmapImageRep:)` already scales points to pixels. Don't scale the context again.

## Findings worth knowing before you code

- WebSocket endpoint is `GET /ws?orchestrationProtocol=2&wsTicket=...`. Missing or wrong protocol version gives HTTP 426.
- Framing is Effect RPC JSON: one JSON message or a JSON array of messages per text frame. Client sends `Request`, `Ack`, `Interrupt`, `Ping`, `Eof`. Server sends `Chunk`, `Exit`, `Defect`, `Pong`, `ClientProtocolError`.
- The server waits for an `Ack` after every `Chunk` before sending the next chunk of that stream.
- Pairing is an OAuth token exchange at `POST /oauth/token` (form encoded), then `POST /api/auth/websocket-ticket` with the bearer token. Pairing tokens expire after 5 minutes. Access tokens last 30 days.
- Authenticated HTTP needs the header `x-t3-orchestration-protocol: 2` or it returns 400.
- `WS_METHODS` in `packages/contracts/src/rpc.ts` lists names the server does not serve, for example `projects.list`. The real list is the `WsRpcGroup` at rpc.ts:1811.
- For the Claude provider, assistant text arrived as one complete `message.updated`. Reasoning text streamed as full-text snapshots every few seconds, not deltas. Plan incremental Markdown around full-text replacement.
- `server.getConfig` is about 80 KB and includes providers, models and keybindings.
- Idle sandbox server: `t3` 0.14% CPU, about 10.7 interrupt wakeups per second, 205 MB footprint. An attached idle `claude` session adds 0.45% CPU and 10 wakeups per second.
